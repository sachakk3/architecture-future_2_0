## 2. Метод MoSCoW

| Категория                                                          | Проблемы                                                                                                            | Обоснование                                                                                                                                                                                                                                                           |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Must have** — без решения цели года недостижимы                  | **P1** (медленные отчёты), **P2** (логика в DWH), **P6** (единая точка отказа), **P8** (доступы/ИБ)                 | Это прямое нарушение двух главных задач руководства: «витрина данных» (P1, P8) и «интеграция новых направлений без вноса логики в DWH» (P2). P6 блокирует миграцию в облако и требование надёжности. Отчётность через часы = задержка управленческих решений (S1, S2) |
| **Should have** — важно, но частично компенсируется Must-решениями | **P4** (кастомизации BI), **P5** (SQL Server 2008 / PowerBuilder), **P9** (time-to-market витрин)                   | P4 закрывается вместе с внедрением Data Catalog + Semantic Layer; P5 — планомерный вывод легаси в течение года; P9 — следствие P1/P2, снижается автоматически после их устранения                                                                                     |
| **Could have** — желательно в горизонте года                       | **P3** (монолит → типовой шаблон доменной платформы для фармы/электроники), **P7** (модернизация интерфейса клиник) | P3 частично покрывается решением P2/P6 (заморозка DWH), полный шаблон онбординга доменов — во вторую очередь; P7 важен, но клиники могут временно работать через мигрированный интерфейс                                                                              |
| **Won't have (этот год)**                                          | Полная замена всех интеграций ESB на Kafka; расширенный AI-анализ мед. данных                                       | Вывод ESB — поэтапный; мед. карты/исследования **сознательно исключены** из витрины данных по требованию бизнеса — их аналитика не входит в объём                                                                                                                     |

## 3. Матрица Эйзенхауэра (важность × срочность)

|              | **Срочно**                                                                                                                                                                                                                                                                                                                     | **Не срочно**                                                                                                                                                                                                                                        |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Важно**    | **Зона №1 — делать немедленно:**<br>• **P1** — отчёты часами блокируют решения уже сегодня (S1, S2)<br>• **P2** — бизнес-логика в DWH блокирует развитие финтеха и ИИ (S4)<br>• **P6** — единая точка отказа: банк и клиники под риском простоя (S7)<br>• **P8** — доступы/ИБ: регуляторные санкции возможны прямо сейчас (S5) | **Зона №2 — планировать:**<br>• **P3** — типовой онбординг доменов фармы/электроники (S6)<br>• **P4** — миграция BI-кастомизаций в витрину данных (S1)<br>• **P9** — self-service процессы анализа (S1)                                              |
| **Не важно** | **Зона №3 — делегировать / минимально:**<br>• **P7** — миграция интерфейса PowerBuilder (делается силами домена клиник в рамках плана вывода легаси) (S3)                                                                                                                                                                      | **Зона №4 — исключить из объёма года:**<br>• **P10** (аналитика по мед. данным) — сознательно вне объёма: мед. карты, истории болезни и результаты исследований не включаются в витрину данных<br>• **P5** завершается сам по мере миграции в облако |

## 4. Итоговый порядок работ (дорожная карта на год)

| Очередь       | Проблемы   | Что делаем                                                                                                                                  | Цели бизнеса              | Сценарии   |
| ------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- | ---------- |
| **Квартал 1** | P8, P6     | Развернуть облачные лендинг-зоны, IAM/SSO, Data Governance; начать CDC-миграцию из DWH                                                      | Комплаенс, надёжность     | S5, S7     |
| **Квартал 2** | P2, P1     | Развернуть доменные data-платформы (медицина, финтех, корпоративный), перенести первые data-продукты и бизнес-логику из DWH в домены        | Скорость, выручка         | S1, S2, S4 |
| **Квартал 3** | P1, P4, P9 | Запустить витрину данных: Data Portal + Catalog + Semantic Layer + Report Builder; мигрировать ключевые BI-отчёты; заморозить DWH на запись | Time-to-market            | S1, S2     |
| **Квартал 4** | P3, P5, P7 | Типовой шаблон доменной платформы для фармы и электроники; вывод PowerBuilder и SQL Server 2008 из эксплуатации; DR-учения                  | Масштабирование, качество | S3, S6, S7 |

**Критерий успеха:** бизнес-пользователи доменов строят отчёты сами за минуты (P1, P9 закрыты), новые бизнесы подключаются без изменений в центральном ядре (P2, P3 закрыты), легаси DWH выведен или заморожен только на чтение (P5, P6 закрыты), доступ разграничен по доменам и срезам (P8 закрыт).
