## Суть архитектурного решения

Целевая модель — **Data Mesh поверх облачной платформы** с четырьмя доменами
(Медицинский, Финтех, Корпоративный, Новые бизнесы) и **витриной данных**
(self-service порталом) как единым окном для бизнес-пользователей.

Ключевые решения:

1. **Доменные data-платформы (Lakehouse)** — каждая из четырёх организаций
   владеет своими данными и data-продуктами; бизнес-логика возвращается
   из легаси-DWH в домены.
2. **Витрина данных (Data Portal)** — веб-портал самообслуживания:
   Data Catalog, Semantic Layer (единые метрики), конструктор отчётов,
   интерактивный query engine к data-продуктам доменов с доступом
   по уровню доступа пользователя.
3. **Kafka как event backbone + CDC** — замена старой шины ESB;
   streaming-инжест событий из финтех-, ИИ- и медицинских систем.
4. **Медицинские данные не анализируются в витрине**: мед. карты, истории
   болезни и результаты исследований остаются в контуре медицинского домена
   (МИС/ЭМК + ИИ-сервисы); в витрину попадают только обезличенные
   операционные срезы.
5. **Легаси замораживается и выводится**: DWH на SQL Server 2008 переводится
   в режим «только чтение» и мигрирует через CDC в домены; PowerBuilder и
   BI-кастомизации заменяются современными сервисами; ESB выводится поэтапно.
6. **Платформенные сервисы**: IAM (RBAC/ABAC), Data Governance (маскирование,
   аудит), Observability/FinOps, геораспределённое развёртывание и DR.

Поддержка ключевых бизнес-сценариев отмечена на диаграмме маркерами **[S1..S6]**.
