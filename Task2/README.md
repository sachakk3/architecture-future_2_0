## Суть решения

Система разделена на **7 доменов** (6 целевых + легаси):

1. **D-MED — Медицинский** (клиники): ЭМК, истории болезни, результаты исследований, расписание, инвентаризация.
2. **D-AI — ИИ-сервисы**: обучающие выборки, модели; работает только с **обезличенными** данными из D-MED.
3. **D-FIN — Финтех** (банк): счета, платежи, кредитный портфель, скоринг.
4. **D-CORP — Корпоративный** (головной офис): KPI, финансовая отчётность, HR.
5. **D-PART — Партнёрские направления** (фарма, электроника): каталоги, договоры, телеметрия оборудования.
6. **D-PLAT — Платформенный**: Kafka + CDC, витрина данных (каталог, semantic layer, конструктор), Master Data.
7. **D-LEG — Легаси-DWH**: заморожен на запись, только экспорт исторических данных через CDC.

**Ключевые правила потоков:** домены не связаны напрямую — только через платформенный слой (события Kafka, контракты data-продуктов, API); мед. данные обезличиваются и не покидают медицинский контур для аналитики (мед. карты, истории болезни и результаты исследований в витрину данных не включаются); новая бизнес-логика в DWH не вносится.

На DFD маркерами **[B1..B6]** отмечено, как потоки обеспечивают бизнес-сценарии: быстрая отчётность, консолидированные KPI, ИИ-анализ мед. данных, запуск нового финтех-сервиса, подключение фармы/электроники, миграция легаси-DWH.
